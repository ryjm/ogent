# Emacs UI ideation

Read the design router and patterns. Use real content and constraints from the audited flow. Compare two or three meaningful directions only when the user asks for alternatives or the design is unresolved: compact section dashboard, dense sortable table, or grouped annotated catalog, for example. Explain the navigation and information tradeoff of each.

Render alternatives in isolated owned buffers, under identical light/dark themes and 60/80/112-column windows. Image generation may communicate mood but is not a faithful Emacs rendering or verification substitute. Do not add web mockups, image-only controls, or fake screenshots. Select the appropriate direction using established user preferences when authorized to implement; ask an optional preference only when it materially changes the product.
