# Emacs UI research

Read `../emacs-ui-design/references/emacs-patterns.md`. Discover packages through adoption and relevance, then inspect pinned upstream READMEs, source, and native screenshots. Stars measure attention, not a universal ranking or proof of usability. Record date, URL, commit, source sections, and what was actually inspected. Do not treat a framework, theme, completion package, and agent client as interchangeable competitors.

Extract a behavior and its purpose, then a bounded ogent adaptation and a way to verify it. Prefer Magit’s stable section identity, Consult/Vertico’s completion metadata, Nano’s restrained hierarchy, Modus’s semantic contrast, Org Modern’s text properties, Elpaca’s contextual filtering, and gptel/agent-shell’s explicit model/context state. Record decisions to reject patterns as well: giant banners, forced global configuration, hard icon fonts, provider setup during browsing, and fabricated evidence.

Read-only upstream clones belong outside the product repository. Cite immutable source links. Reuse ideas; do not silently copy assets, code, branding, or private skill text. No upstream code must execute merely to research it.
