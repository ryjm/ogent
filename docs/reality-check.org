#+date: 2026-10-08

* Assessment

The model catalog refresh is delivered: the registry browser displays all
seven current OpenAI/Anthropic models offline. The project has substantial
real implementation, including Org storage, context composition, edit review,
CLI adapters, canonical conversations, scheduling and operational UI.
It is not verified as a reliable complete agent workflow.

The most immediate failure is ordinary OpenAI dispatch with current gptel:
its constructor creates a Responses backend, which ogent's provider resolver
rejects. Independent confirmed failures affect stale multi-edit acceptance,
MCP arguments and tool audit recording. Passing unit tests and closed beads
have missed these integrations.

This is an assessment and implementation plan. Runtime fixes are tracked below;
this audit does not claim to implement them or verify live provider access.

* Confirmed gaps and bridge plan

** G1: Provider family and endpoint are conflated (P1)

Current gptel's =gptel-make-openai= detects api.openai.com and creates
=gptel-openai-responses= at =/v1/responses=. That struct includes
=gptel-backend=, not =gptel-openai=. Its constructor docstring still describes
Chat Completions; the executable constructor is the evidence.

=ogent-gptel-backend-matches-provider-p= tests =gptel-openai= only, and
=ogent-gptel-resolve-backend= returns the unresolved provider symbol.
The documented =ogent-run-subtree= path then reports "Backend ... not loaded".
This affects API-key onboarding as well as manually configured stock backends.

Older/custom Chat Completions backends have a separate compatibility problem:
Sol function tools require Responses, and Luna's Chat Completions override
must not be blindly sent to Responses. Official model references:
[[https://developers.openai.com/api/docs/models/gpt-6.1-sol][Sol]] and [[https://developers.openai.com/api/docs/models/gpt-6-luna][Luna]], consulted for the catalog refresh.

Plan: preserve explicit backend objects/configuration; classify provider
families across sibling transport structs; model endpoint/tool constraints
explicitly and validate actual request shapes. Keep old IDs and user choices,
with actionable compatibility hints. Never silently downgrade reasoning.

Files: [[file:../lisp/ogent-gptel.el][ogent-gptel.el]], [[file:../lisp/ogent-models.el][ogent-models.el]], onboarding and all chat/edit/codemap/Babel/native call sites.
Acceptance: normal onboarding-to-Org dispatch serializes the chosen model on
both supported endpoint types with actual minimum/current gptel; incompatible
choices fail clearly before HTTP. Complexity M/L. V1/V2/V4/V12.
Beads: =ogent-xmn= then updated =ogent-io4=; companion =ogent-bpx=.

** G2: Multi-edit review can corrupt unrelated text and miss the audit log (P1/P2)

=ogent-edit-diff--apply-edit= deletes cached positions without re-anchoring.
Validate old->new in "old-tail", prepend "PREFIX ", then accept:
expected "PREFIX new-tail", actual "newFIX old-tail", status accepted.
The resolution hook fired zero times.

The closed =ogent-tdf.1= fixed the smerge display path. The closed
=ogent-tdf.2= fixed the single-edit preview. Neither close reason proves the
multi-edit review path. This is incomplete fix scope, not proof that those
other paths regressed.

Plan: use shared exact-text re-anchoring, preflight batches by source buffer,
reject missing/ambiguous/overlapping edits without losing proposals, and
route successful accept/reject through shared untracking/resolution hooks.
Keep single/staged/batch behavior, source undo and companion logging.

Files: [[file:../lisp/ogent-edit-diff.el][ogent-edit-diff.el]], edit display/log, mirrored tests.
Acceptance: source mutation between preview/accept cannot overwrite unrelated
text; all four review decisions log/untrack once; failed applies log no
resolution and remain recoverable. Complexity M. V5.
Beads: reopened =ogent-tdf.1= -> reopened =ogent-tdf.2=; =ogent-bpx= verifies.

** G3: MCP receives empty arguments from real tool callers (P1)

Registered wrappers receive positional values from gptel and the canonical
UI executor. =ogent-mcp--args-to-alist= consumes keyword pairs.
A registered tool with required path, called with "/tmp/example.txt", sent
=((name . "read") (arguments))=. Discovery/schema/converter tests pass
separately without exercising this contract boundary.

Plan: map values through the advertised schema; preserve optional/false/null,
object/array and zero-argument object shapes. Refresh cached gptel specs on
schema changes/reconnect and remove disconnected capabilities.

Files: [[file:../lisp/ogent-mcp.el][ogent-mcp.el]], model tool registration/cache, MCP tests.
Acceptance: model-shaped tool call reaches a fixture server with the exact
RPC object; refreshing/removing a schema cannot retain stale cached behavior.
Complexity M. V7. New =ogent-b9j=; companion =ogent-bpx=.

** G4: Real gptel can execute tools outside the promised ledger path (P1)

=ogent-register-tools= installs raw tool functions. Actual
=gptel--handle-tool-use= auto-executed a read-file fixture while the ogent
ledger was enabled; result contained the file text, ledger file did not exist.
=ogent-armory-native--handle-tool-results= records a transcript after that
execution but cannot retroactively enforce policy or record start/finish.

Code also shows native handling of pending =(TOOL ARGS RESULT-CALLBACK)=
ignores RESULT-CALLBACK and starts a fabricated new request. The original
FSM lifecycle, async tools and iteration/abort ownership need real-gptel
fixtures; no live failure of that continuation was claimed here.

Plan: give execution one owner, bridge approval/deny/allow, workspace and
ledger for both automatic and confirmed calls, consume callbacks exactly
once, and retain correct protocol tool messages/cleanup.

Files: [[file:../lisp/ogent-armory-native.el][ogent-armory-native.el]], model registration, UI tool callbacks.
Acceptance: one execution, one policy decision, one ledger start/finish,
one completion; no orphan pending FSM or follow-up after cap/abort. Async
callbacks work under the actual library. Complexity L. V6/V12.
Bead reopened =ogent-wfv.6=; companion =ogent-bpx=.

** G5: External skill discovery is narrower than the advertised roots (P2)

=ogent-armory-skill--org-files= ignores SKILL.md. A valid package under
=.codex/skills/audit/SKILL.md= yielded an empty catalog. This includes the
format JSM installs. Manual =ogent-armory-skill-import= with an explicit key
can import the text into Org; automatic external-package discovery cannot.

Plan: read external package metadata/body without evaluating it; retain
Org durable output, provenance, lazy loading, distinct package keys,
collision precedence and reference paths. Do not automatically duplicate
packages into a second store. Complexity M. V15.
New =ogent-ikh=; companions =ogent-bpx= and =ogent-7omc=.

** G6: Green CI does not prove the runtime dependency boundary (P1/P2)

CI unit jobs load =ogent-test-helper.el= without installing gptel. The helper
provides fake features and fallback request/preset definitions. Useful local
contracts pass, but constructor/resolver/callback/serialization mismatches
are outside that evidence. Lint installing dependencies is not runtime proof.

Sandbox failures are separately explained by the tripwire trusting all of
=temporary-file-directory= while makem places =user-emacs-directory= inside
that tree. Deliberate "real store" test paths become sanctioned.

Plan: retain fast unit CI, add minimum/current real-dependency offline
journeys using loopback HTTP/SSE and fixture CLI/MCP processes, and make
protected-store fixtures independent of config location. Log versions,
model/endpoint, IDs/counts/cleanup and Org artifacts without secrets.

Acceptance: required checks pass in sandbox and non-sandbox; actual setup,
request/tool/edit/native/MCP paths run offline without contacting providers.
Snapshot whitespace failures require a separate compatibility fix/support
choice; do not label optional failure success. Complexity L for proof,
M for harness. V2-V7/V12/V18. New =ogent-bpx= and =ogent-nr0=.

** G7: Broad local Armory parity remains an integration proof gap (P2)

Canonical conversations, continuation, adapters, schedules, actions,
settings, data, git and UI are implemented. A native invocation returning
no external program is not a stub: runner dispatch routes it to the native
loop. A keyword scan cannot establish missing functionality here.

Plan: actual Org-file/fixture-process journeys from scaffold/import through
composer, attachments, run, continuation/replay, events/artifacts/task lanes;
fixed-clock schedule/action/restart journeys; local data/search/git/settings/
backup operations. Map every parity acceptance clause to evidence or an
explicit remaining issue. CLI help snapshots prove invocation plans, not
provider executable compatibility or model access. Complexity L. V10-V16.
New =ogent-7omc=; preserve intentional sidebar/org-attach/daemon exclusions.

** G8: Cost estimates and public status need reconciliation (P2/P3)

The new model rows are current base rates, not complete bills. Legacy rows
still have an open official-source audit. Haiku 5.5 over 100K input, caching,
service tiers and other context premiums are not represented by a flat table.

ROADMAP's "no critical gaps" statement is false. Its missing-template/backend
claims are stale. Armory parity's Current Gaps/Parity Matrix contradict its
July shipped note and actual canonical store/settings/provider/schedule code.
Do not implement those already-shipped features again to satisfy stale prose.

Plan: official dated row evidence and threshold tests or clearly labeled
base estimates; reconcile one current status source with code, journeys and
beads. Preserve historical decisions without presenting them as current.
Acceptance: each public acceptance clause has verified evidence or an honest
limit/issue; no unsupported coverage/performance/complete-parity claim.
Complexity M. V8-V18. Existing =ogent-83c=, new =ogent-mgcr=.
